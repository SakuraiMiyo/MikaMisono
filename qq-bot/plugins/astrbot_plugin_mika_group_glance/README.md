# 未花 · 刷群（group glance）

## 它解决什么

AstrBot 核心的唤醒机制是「不 @ 就完全不看不回」——真实的人不是这样：
人会**刷到**群消息（看到了、有印象），只是大多数时候**懒得回**。
本插件把这个状态补上：

1. 每条群消息都进缓冲（零 LLM 成本）；
2. 按「看一眼概率」采样，让模型用一次**便宜的判断调用**审视最近几条；
3. 判断「不回」→ 记入“看过没回”缓存，什么都不发——模拟人刷到但没接话；
4. 判断「回」→ `event.request_llm` 走标准管线，针对触发消息回复
   （人格、分段、括号、TTS、防思考泄漏补丁全部生效，回复记入会话历史）。

## 防护（都可在配置调）

- **冷却**：采样命中后 N 分钟内不再看（默认 20 分钟）
- **每日回复上限**：判断为「回」的次数封顶（默认 5 次/天）
- **免扰时段**：默认 01:00–07:30 不看不回
- **巡逻衰减**：连续 3 次「不回」把采样概率减半（最低降到配置的 1/4）——避免像巡逻机器人
- **群白名单**：默认只开测试群
- **判断调用永远不发消息**：它是纯 text_chat，输出 JSON 不会进群；
  只有 `request_llm` 走管线的正式回复才会被发送

## 判断的倾向（写死在判断提示词里）

大多数消息不回。回的理由只有：有人直接跟她说话 / 问到她 / 她能提供独特价值 /
戳中她憋不住的兴趣（编程、甜食、瑞士卷、枪械、时尚首饰、格黑娜八卦）。
纯水群、接梗刷屏、和自己无关的讨论 → 不回。

## 配置（面板里改）

看 `_conf_schema.json`。改完保存即生效（插件配置是现读的）。

## 和现有体系的关系

- `astrbot_plugin_reread`（复读）互不影响；
- `poke_to_llm`（戳一戳）互不影响；
- 看过没回的记录存在 `data/plugin_data/astrbot_plugin_mika_group_glance/seen.json`，
  将来可接 on_llm_request 注入（「你刚才刷群看到了这些但没接话」）。
