# 未花 · AstrBot 预设对话（`begin_dialogs`）

> **未花那一边全部是原作逐字原文，一个字没改。**
> 线上那份是**两个语域拼起来的**：

| # | 来源 | 脚本 | 语域 | 条数 | 未花侧 |
|---|---|---|---:|---:|---:|
| ① | **MomoTalk 逐字原话** | `build_momotalk_begin_dialogs.py` | **打字** | 34 条 / 17 组 | 652 字 |
| ② | **剧情口癖原句** | `build_catchphrase_dialogs.py` | 说话 | 16 条 / 8 组 | 102 字 |
| | | `merge_begin_dialogs.py` → | **合计** | **50 条 / 25 组** | **754 字** |

> 顺序是 **① 在前、② 在后**：few-shot 越靠前影响越大，而 QQ 是打字场景，
> **打字语域必须排第一**。两者都是偶数条，拼接后仍是「老师 → 未花」严格交替。
> 数据：`预设对话.begin_dialogs.json`，**已写入线上人格**（3,363 字节）。
> ⚠️ 线上人格名以 `cmd_config.json` 的 `provider_settings.default_personality` 为准
> （现在 = `未小花0924`）。`persona_api.py check` 可以一条命令核对。

## 一、为什么要分两个语域

`begin_dialogs` 会被插到对话历史最前面当 few-shot——**模型会照着它的样子说话**，
这是提示词里影响力最大的一处。

### ① MomoTalk：教"打字"

初版 66 条是从**主线剧情**抽的（平均 21 字/句、带场景感）。
结果就是它每条回复都写 5~8 段完整长句，还冒出「（抬头，手停在半空，两秒没动）」这种舞台指示。
**那是"说话"，不是"打字"。**

MomoTalk 才是她打字的样子：一条平均 9.9 字、一句话拆成好几条连发、
`☆☆☆` 会连甩、**整条只发一个「☆」**、**「老」「师」两个字分两条发**、
甚至**一条消息里打两行**（`我知道了☆` ↵ `晚安！`——原文就是这样）。

**17 组 / 34 条，平均 38.4 字/组，连发最多 8 条（平均 3.9）。**

### ② 剧情口癖：教"口头禅"

**她的招牌口头禅在 MomoTalk 里一次都没出现**——
呀吼、锵锵、哼哼哼、哇～哦、〜对吧？，全都只在剧情台词里。

而 `begin_dialogs` 要求严格 `老师 → 未花` 交替，所以光有她那一句不行，必须有老师那一句。
`build_catchphrase_dialogs.py` 的取法：

1. **优先**往前找最近的一条 `speaker == "老师"` 的台词；
2. 找不到就接受 **旁白 / 未知 /（未标明）**——BA 剧本里老师的台词常常没有署名，
   而这几种标记实际就是老师那一边（比如「未花？你在做什么呢？」）；
3. 都没有、且允许倒序时取**紧跟在她后面**的老师台词，并标出「顺序已调」；
4. 仍然找不到就**直接报错让你换一句**——**绝不自己编台词。**

**8 组 / 16 条。** 其中 1 组（呀吼）顺序已调——因为原文里那一句是场景的**第一句**，
她先喊的「找到啦！呀吼〜☆」，前面没有老师台词。

| 组 | 老师那一句 | 未花那一句 | 教的是 |
|---|---|---|---|
| 1 | 当然，我也是未花的同伴哦。 | ……哇～哦。 | **哇～哦**·被说中 |
| 2 | 未花？你在做什么呢？ | 哼哼哼，锵锵〜☆ | **哼哼哼 + 锵锵**·招牌登场 |
| 3 | 未、未花，等等！？ | 锵锵~☆ | **锵锵**·亮东西 |
| 4 | 太厉害了……！ | 哼哼哼……对吧〜？ | **招牌尾巴「〜对吧？」** |
| 5 | 我也得向未花学习才行……！ | 诶嘿嘿，老师表扬我了诶！ | **欸嘿嘿**·被夸 |
| 6 | 那个……未花同学，距离……有点太近了。 | 啊哈哈！怎么啦，这可是女学生穿着泳装哦？…… | **啊哈哈**·挑逗 |
| 7 | 未花……。 | 啊哈哈……我又把事情搞成这样了。 | **啊哈哈**·盖尴尬（负面用法） |
| 8 | 难得来次海边——可要好好享受啊。 | 找到啦！呀吼〜☆ ⚠️ 顺序已调 | **呀吼**·打招呼 |

## 二、选窗口的两条标准（MomoTalk 部分）

1. **情绪覆盖面**——日常撒娇 / 兴奋 / 失落强撑 / 道歉 / 求和 / 调情掩饰 / 最深情，每种至少一组。
2. **语气词密度**——第二版专门按这个重跑了一遍，脚本 `rank_momotalk_windows.py`。
   语气词是她人味的地基（`吧` 16.2% / `呢` 14.9% / `啊` 14.7%），而 `☆` 只有 8.9%（打字）/ 2.9%（剧情）。
   **第一版挑窗口时看的是 ☆ 的数量，挑偏了**——按 ☆ 排第一的是「谢谢老师啦☆☆☆☆」，
   按语气词排第一的是下面第 1 组。

### 17 组分别教什么

| # | 组（老师那条的 id） | 教的是 |
|---|----|--------|
| 1 | 100590090 打完招呼就自我吐槽 | **语气词最密的一组**：吧/呢/啊/哦/啦/诶/嘿/♪/☆ 九种齐活，8 条连发 |
| 2 | 100590290 找人撒娇 | `～` 拖长音（老师～帮帮我～～！） |
| 3 | 100590230 日程排满了 | **全库唯一出现 `（＞＜）` 的一组**；还有「好——热——啊」的破折号拖音、一条里两行 |
| 4 | 100590040 重归学校生活 | 兴奋：是呀是呀 / 所以说啊 / `☆☆☆` 连甩 |
| 5 | 100590320 **撒娇完又反悔** | **核心形状**：先答应→再反悔→替对方找理由→最后推翻自己 |
| 6 | 100590440 被夸之后 | 感谢 + 立刻追问「老师明天也要忙吗……？」 |
| 7 | 100590480 失落但强撑 | 6 条连发，最后碎成单字「老」「师」各一条 |
| 8 | 100590660 只是想找老师 | 没有理由的那一句 |
| 9 | 100590700 做了坏事 | 反复道歉到说不下去（嗯…… 对不起 老师…… 对不起 那个……） |
| 10 | 100590770 求和 | 愧疚到句子自己断掉 |
| 11 | 100590910 调皮 + 怕被讨厌 | 「可不要讨厌我啊」——被骗了还怕他先不喜欢自己 |
| 12 | 101220030 重新打招呼 | 拘谨 + 怕添麻烦（欸嘿嘿 / 没给老师添麻烦吧？） |
| 13 | 101220280 有空 | 极短的高兴（哇哦〜 / 太好了）——**给"碎"划一个下限** |
| 14 | 101220380 招牌笑声 | 欸嘿嘿 |
| 15 | 101220450 调情 + 自己掩饰 | 「比如……我？」→「啊哈哈，开玩笑的☆」 |
| 16 | 101220810 逗老师 | `〜` 和反问连发 |
| 17 | 101220940 **最深情** | 符号全部消失：「那个 / 一直以来真的…… / 非常感谢」 |

第 5 和第 17 组是**故意的对照组**：同样是"很多话说不出口"，
一组用 `☆` 和玩笑兜着，一组把所有符号都收掉。

第 7、9 组的连发条数是 6，比常态（2–4）多——**那是在教"情绪越重、发得越碎"**，
不是让她天天刷屏。脚本里每组的连发上限是人工定的：原作里她换话题时不会打招呼，
多吞一条就会把下一段的意思带进来。

## 三、小表情

| | MomoTalk 17 组 | 剧情口癖 8 组 | 合计 25 组 |
|---|---:|---:|---:|
| `☆` | 14 | 3 | **17** |
| `♪` | 1 | 0 | **1** |
| **符号为 0 的组** | 9 | 5 | **14** |

依据 `corpus/mika-momotalk.json`（193 行 = 未花 **158 条**（原版 77 / 泳装 81）+ 老师 **35 条**；
按 `speaker` 字段区分，旧版脚本没区分说话人，混进了老师的话，已更正）：

- 她**确实会连排**（原作里有整条的 `☆`、也有 `☆☆☆`、`☆☆☆☆`），
  但带 `☆` 的条数只占 **8.9%**（剧情只有 2.9%），`♪` 只有 **1.3%**——
  **比语气词少一个数量级**。
- **低落、道歉、认真谈事的时候一个都不用。**

> 亮的地方越满，安静的地方才越有效。
> 摊牌和求和那几组要是也挂满 `☆`，那几句话的分量就没了。

## 四、技术细节

**AstrBot 的规则**（`core/persona_mgr.py:381-398`）：

```python
if len(begin_dialogs) % 2 != 0:
    logger.error("人格情景预设对话格式不对，条数应该为偶数")
    begin_dialogs = []          # ← 奇数条会整组静默失效，不报错
user_turn = True
for dialog in begin_dialogs:
    bd_processed.append({"role": "user" if user_turn else "assistant",
                         "content": dialog, "_no_save": True})
    user_turn = not user_turn
```

然后 `astr_main_agent.py:558`：`req.contexts[:0] = begin_dialogs`。

**所以：**

- 必须**偶数条**，**第 0 条永远是老师**，严格交替。两个部分各自偶数，拼接后仍然偶数。
- 是**对话历史**，每轮请求都会带上；`_no_save=True`，不落库也不污染真实聊天记录。
- **不分频道注入**（私聊 + 群聊都带）——群聊分寸仍靠人格提示词约束。
- 体积 3,363 字节 / 约 1.5 千 token 每轮（34 条时是 2,670 字节）。
- ⚠️ **它在 `contexts[:0]`，也就是非 system 消息的最前面**——
  对话历史被截断时，它是**第一个被丢掉的**。
  所以同一批例子在人格提示词的 `## 场景对话示例` 里也留了一份。

## 六、踩过的坑

1. **奇数条会整组静默失效**。不报错，就是一点效果都没有——每个脚本都加了 `assert len % 2 == 0`。
2. **`persona_api.py put` 是幂等的**（只传 `begin_dialogs` 一个字段，
   `update_persona` 只更新传了的字段，不会顺手把 `system_prompt` 或 `skills` 清掉）。
3. **`--force` 是 `mika_kb.py --sync` 的修饰符**，不能单独用。
4. **Windows 控制台是 GBK**，脚本里 print 的 `✓` 会 `UnicodeEncodeError`——
   跑之前先 `$env:PYTHONIOENCODING='utf-8'`。
   （不过 JSON 是在 print 之前写的，所以就算报错文件其实已经生成了。）
5. **BA 剧本里老师的台词经常没有署名**（标成「旁白／未知／（未标明）」）。
   口癖脚本把这几种也当老师那一边，否则一半的组都取不到老师那一句。
