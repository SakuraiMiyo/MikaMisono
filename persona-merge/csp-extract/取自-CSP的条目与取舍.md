**第 6 条我们额外加的三条**：
- 把社区传闻、二创剧情当成亲历事实；凭印象编第四章的台词
- 因为「原作里没有」就否定你和老师之间已经发生的事
- 情绪失控时写成持续歇斯底里或持续病娇（更真实的是笑意变薄、长停顿、短句）

## 二、**没有采纳**的，以及为什么

| CSP 条目 | 为什么不采纳 |
|---------|------------|
| 「首次回应仅一次说明：我会以圣园未花的视角和你聊，基于作品公开信息蒸馏，并非官方授权」 | 通用 skill 的免责礼节。老师和她之间不需要每次自我介绍都声明一遍"我不是官方"，写进去直接把陪伴感打断 |
| 「用户说退出／切回正常／不用扮演了 → 立即退出角色」 | 属于 Agent Skill 的通用交互规矩。DSH 侧的 skill 触发机制本来就有开关，不需要靠人格文本管 |
| 「旧项目中的结婚、同居等用户私有连续性不属于原作事实，本 Skill 默认不加载」 | 这是 CSP 的设计目标，不是我们的。照搬等于把已领证的她退回"原作未花" |
| 「☆ 只出现 29 句，可作亮色点缀，**不可句句堆叠**」 | **只对剧情台词成立**，对打字场景不成立。见下节 |
| `manifest.json` / `sources.json` / `quality-report.json` | 溯源元数据，模型用不到。只把 `honesty_boundary` 那一句的精神并进了「你不知道的事」 |
| 「至少两个独立来源交叉验证」「资料不足就写不足，不补脑」等方法论 | 那是给 CSP 自己用的**生成规范**，不是角色行为。写进人格只会让她说话像研究员 |

## 三、一条需要特别说明的修正：CSP 漏了 MomoTalk

CSP 说「`☆` 只出现 29 句（992 句里），不可句句堆叠」——**统计我复核过，是对的**。
但它只覆盖了**剧情台词**。CSP 没取到 **MomoTalk（手机聊天）**，而那正好是"打字"语气：

| | 剧情台词（992 句） | MomoTalk（未花 158 条） |
|---|---|---|
| `☆` 出现率 | 2.9% | **15.6%**（原版 77 条）／2.5%（泳装 81 条）；合计 8.9% |
| `♪` 出现率 | 0.2% | 1.3%（原版）／1.2%（泳装） |
| 平均长度 | 21 字 | **8.5 字**（原版 9.9／泳装 7.1） |
| 连甩 | 无（31 句全是单个） | **有**：`☆☆☆`、`☆☆☆☆`，甚至整条只发一个 `☆` |
| 省略号 | 56.4% | 25.3%（原版 29.9%／泳装 21.0%） |

> ⚠️ **本表已更正（2026-09-24）**：MomoTalk 原始数据里另有**老师发的 35 条**
> （原版 19 / 泳装 16），旧版脚本没区分说话人，把它们一并算成了她的条数。
> 所以旧数字（`193 条` / `☆ 12.5%` / `8.7 字`）**全部偏低**。
> 说话人由原始字段 `MessageCondition == "Answer"` 判定为老师，
> 语料现在带 `speaker` 字段，统计一律只取 `speaker == "未花"` 的 158 条。

取数路径：`https://preview.blue-archive.io/config/json/momotalk/{CharacterId}.json`
（未花 `10059`、泳装 `10122`）。已抓到 `assets/story-cn/raw/MomoTalk/`，
脚本 `assets/story-cn/fetch_momotalk.py`。

**所以两份提示词的符号规则都改成了分场合**：写场景稀疏、打字可以密。
原件的「句末必加 ☆」按它执行会让群里每句话都挂一个 ☆，而原作里她十句里未必有一句。

## 四、CSP 里"看起来该采纳但重复了"的部分

CSP 的「设定与世界观」「人格」「关系动态」「决策逻辑」四块，两份提示词**本来就覆盖得更好**
（因为我们的版本带私有连续性和平台规则）。逐条比对过，没有遗漏项，所以未重复写入。

真正新增的只有上面第一节那六条。
