## 二、两条链路的差异（必须记住）

| 维度 | ① QQ 侧 | ② DSH 侧 |
|------|---------|----------|
| 服务对象 | QQ 群聊 + 私聊（老师 & 群友） | 本机 DSH agent 对话（只有老师） |
| 人格真源 | `qq-bot\persona\bot-personality.md` → 灌进 AstrBot persona 表 | `agent\SKILL.md` → 生成 DSH persona patch |
| 人格存在哪 | AstrBot SQLite（`data_v4.db`） | DSH 的 `cordis.patch.yml` + skill 文件 |
| 记忆 | companions.json + kb.db + 插件自带引擎 | `agent\memory\`（日记 / 记忆卡 / 向量库） |
| 说话规矩 | 群聊一句话、不主动写动作、句末加 ☆ | 三层输出（场景/动作/内心）、可长可短 |
| 能不能看到对方 | 不能 | 不能 |
| 谁在跑 | AstrBot Desktop + NapCat（常驻） | DSH Desktop（常驻） |

> ⚠️ **两条链路的人格不会自动同步。** 改了 QQ 侧的角色设定（年龄、外形、经历、称呼），
> 要手动同步到 `agent\SKILL.md` 的对应章节；反过来也一样。
> 平台专属的规矩**不要互搬**（群聊规矩别进 DSH，三层输出也别硬套到群聊）。

## 四、⚠️ 待接线：dsh-bridge 在空转

**现状（2026-09-24 实测）**

| 检查项 | 结果 |
|--------|------|
| `dsh_bridge.py` 进程 | ✅ 在跑（开机自启 `启动\start_dsh_bridge.bat`） |
| 端口 8808 | ✅ 监听中，`/v1/models` 返回 `{"id":"dsh"}` |
| AstrBot `provider` 里有 `dsh/dsh` | ❌ 没有（只有 gsv_tts、deepseek-flash、gemini flash） |
| `mcp_server.json` 里有 dsh | ❌ 没有（只有 mcd、yun） |
| 结论 | **QQ 机器人由 deepseek-flash 直连回答，桥接没有被调用** |

**这意味着**：手册里画的「QQ → AstrBot → dsh-bridge → dsh Agent」这条链，现在只成立了前半段。
想让 QQ 回复也走完整 Agent（工具、文件、技能全部生效），需要恢复接线 —— 步骤见
`docs\dsh接入AstrBot桥接.md` 第四节。

**恢复接线的影响面**：会改动线上 QQ 机器人的模型配置（响应变慢 5~30s，但获得完整工具能力）。
**建议单独开一轮、老师在场时做，不要顺手改线上。**

## 六、踩过的坑（都别再踩）

| # | 坑 | 教训 |
|---|----|------|
| 1 | **记忆守护静默失效** | 单实例锁用 `PID 还活着` 判断，Windows 复用 PID 后新实例会误判"已在跑"而退出。守护已删除，改为手动 `auto.mjs`。 |
| 2 | **persona 生成器锚点失配** | `gen-persona-patch.mjs` 靠固定句子定位插入点，改 SKILL.md 时动了那句话，注记就静默丢失。**改完必须核对 persona 里有没有「知识库根目录」那行。** |
| 3 | **PowerShell 脚本丢 BOM** | `deploy_mika.ps1` 存成无 BOM 的 UTF-8 后，PS 5.1 按 GBK 解析，中文全乱、脚本语法崩。**改完先 `Parser::ParseFile` 验证 + 确认前 3 字节是 EF BB BF。** |
| 4 | **两份人格各自为政** | 线上 DB（649 行）与本地真源（848 行）**双向**都缺东西：线上有「中间步骤输出禁令」，本地有 199 行知识库与说写规矩。已把线上的禁令合并回真源。**改人格前先对账。** |
| 5 | **standard preset 遮蔽全局 persona** | 应用升级会覆盖安装目录里的 `disabled: true`，升级后必须复查。 |
