## 2. 说话人是怎么判定的（**这是本库最值钱的部分**）

剧情 JSON 的每个单元长这样：

```json
{
  "TextCn": "……我还以为我们永远都不会再见面了。",
  "TextJp": "……もう二度と会えないと思ってたのに。",
  "ScriptKr": "1;미카 비무장;02;이제 못 볼 거라고 생각했거든.",
  "BGName": 914457591, "BGMId": 73, ...
}
```

- `TextCn` 是社区中译，**没有说话人字段**。
- `ScriptKr` 是**韩国原版演出脚本**，每行一条命令：

```
{槽位};{角色名};{表情编号}[;{台词}]      例：1;미카 비무장;02;이제 못 볼 거라고…
#na;{角色名};{台词}                    例：#na;미카;시라스 아즈사야.   ← 角色旁白
#na;{文本}                            纯旁白（只有两段）
#3;a  /  #wait;1500  /  #bgshake…     演出指令，不是台词
```

所以 **`ScriptKr` 里第 4 段非空的命令，其角色名就是这句话的说话人**。

### 踩过的三个坑（下游请勿重犯）

1. **槽位号不等于角色。** 早期版本假定「未花永远在 3 号槽」，结果她一旦站到 1 号槽就全漏。
   实测槽位在 1–5 之间随机变化。**必须按角色名字段取，不能按槽位取。**
2. **`#na;{角色};{台词}` 是独立的说话人形式。** 未花最长的一段独白（32010 讲圣三一历史，
   3,652 汉字）**全部**走这个形式。漏掉它，等于把她最有分量的一段台词整段丢掉。
3. **旁白里出现「未花」≠ 未花在说话。** 原文大量存在「未花同学因为在校内和别人产生了
   暴力冲突……」这种第三人称叙述。按关键词匹配会把这些全算成她的台词。

### 韩文角色名 → 中文

映射表在 `ba_speaker.py` 的 `SPEAKER_CN`。未花有 6 个变体，全部归并到「未花」，
但 `.json` 里保留了 `speaker_kr` 原值，方便按服装细分：

| `speaker_kr` | 含义 | 句数 |
|--------------|------|-----:|
| `미카` | 未花（常服） | 500 |
| `미카 수영복` | 未花（泳装） | 279 |
| `미카 비무장` | 未花（无武装 / 便服态） | 177 |
| `미카 케이프오프` | 未花（披风脱落） | 15 |

## 4. 蒸馏怎么用（建议）

### 方案 A：RAG / 提示词（推荐先做这个）

- 用 `corpus/mika-scenes.jsonl` 建向量库：每条是一个完整场景窗口（她的台词 + 对手台词 + 立绘）。
- 用 `未花-剧情时间线.md` 作为**结构化的剧情索引**塞进系统提示，让模型知道
  「她现在是哪个阶段的未花」（狱中 / 羁绊日常 / 战后）。
- 关键：**分阶段检索**。狱中期的她和泳装羁绊里的她语气差异极大，
  混在一个向量空间里会互相污染。建议按 `cat` + `story` 分开建库。

### 方案 B：SFT

- 直接用 `corpus/mika-pairs.jsonl`：992 条 `{context, reply}`。
  上下文已经保留了说话人标签（`sp`），可以拼成 `老师：… / 未花：…` 的对话格式。
- `emote` 字段是**可靠的情绪标签**（来自游戏原始的情绪气泡命令 `#槽位;em;[X]`，
  如「闪亮」「冷汗」「脸红」「难过委屈」），992 句里有 322 句带标签。
  `sprite` 是立绘资源号，**没有情绪含义**，别当标签用。详见时间线第七节。
- 数据量对全参微调偏小，建议 LoRA + 与通用对话数据混合，别单独训。

### 方案 C：风格指纹分析（不训练，只做画像）

`corpus/mika-only.md` 是 992 句纯台词，适合直接丢给模型做「语气特征归纳」：
句长分布、☆♪ 使用频率、自嘲句式、第二人称称呼方式、句尾助词偏好等。

## 5. 已知局限（**请一并转达给下游**）

0. ⚠️ **覆盖范围不是「全部 Vol.3」，只是前三章。**
   **Vol.3 第四章「忘れられた神々のためのキリエ」（Kyrie for the Forgotten Gods，
   前/中/後編，2022-05-25 / 06-08 / 08-10 配信）整章缺失**，而那一章才是未花
   救赎弧的正戏。当前 992 句里没有这一章的任何一句。
   佐证与取证过程见 `未花-剧情时间线.md` 第八节第 1 条、`game/README.md`。
   **拿到第四章后，本文档所有统计都要重算。**
1. **9.3% 的对话轮没有说话人**（582 条 `未知` + 77 条 `（未标明）`）。
   游戏原始脚本里有一批文本框用 `[s1][s2]…` / `[ns1][ns2]…` 的多格写法，
   **本来就不告诉玩家是谁在说**（用途：神秘人物、众人齐声、旁白与对白混排）。
   在未花出场的 25 篇里这类行共 **158 条**，在 `mika-turns.json` 里 `conf: "none"`，
   `speaker` 标为 `未知` 或 `（未标明）`。**它们不是未花的话，但也不能排除。**
2. **活动「夏空のやくそく」（4.5 周年，Vol.3 后日谈）原文缺失。**
   已核对 ba-archive（main + preview）、1788 个 event id、bawiki-data、SchaleDB、
   HuggingFace —— 公开库都没有。目前只有人工概要 `夏空のやくそく_概要.md`。
   **这是她弧光的正式收尾，缺了它模型只有结局没有过程。**
3. **「垂怜经 / Kyrie Eleison」场景在第四章，不在本语料里。**
   早先这里写的是「找不到对应段落，可能只是技能名」——**那个结论错了**，
   错因是把「源站只有三章」当成了「Vol.3 只有三章」（见第 0 条）。
   事实：未花在第3章第17话（33170）崩溃后到尾声（33250）之间确实一句台词都没有，
   但那段空白**对应的正是第四章「忘れられた神々のためのキリエ」**。
   所以：**不要因为语料里没有就断言这个场景不存在。**
   引用标题时用日文原名；英文社区常见的 "Kyrie for the Students" 是意译偏差。
4. **`sprite`（立绘资源号）没有情绪含义**，别当标签用；情绪请用 `emote`。
   但**服装变体是时间线信号**：`미카`（常服）→ Ch1/Ch2 + 原版羁绊；
   `미카 비무장`（无武装）→ 失势之后的 Ch2 末～Ch3（狱中）；
   `미카 수영복` → 泳装羁绊；`미카 학교 체육복`／`미카 케이프오프` → 100593；
   `미카 학교 수영복` → 100596。
5. **数据源是社区翻译**，不是官方中文。译名可能与官方不一致
   （如「圣娅/圣亚」两种写法在语料里并存，已在映射表里统一为「圣亚」）。
6. **中文文本里有演出标记残留的可能**。清洗规则已覆盖实测到的全部标记
   （`[ruby=]` `[tooltip=]` `[wa:N]` `[log=]` `[FF6666]…[-]` `[USERNAME]` 等），
   但若下游发现漏网的，改 `ba_speaker.clean_text()` 后重跑 `build_corpus.py` 即可。
7. **还有 6 个次要 NPC 没有说话人中文名**（`아유무` `마이` `쿠즈노하` `아오이` `소라`
   `데칼코마니`，合计 96 条，占 1.35%）。剧情站的 `students.json` 里没有这几个，
   且都在语料里只出现个位数到二十几次，**与未花无关**，所以原样保留韩文没有强行猜译。
   其余 7,014 条（98.6%）的说话人已全部中文化（含杂兵 A/B/C）。
8. **「本地目录 ↔ 源站目录一致」证明不了收全了。** 那个目录表是从同一个源站抽的，
   属于自洽性检查。踩过的坑：曾经硬编码 `31000 <= i < 34000` 把 Ch4 排除，
   再用自己抽的目录去比自己的结果，报了个漂亮的「✅ 一致」——**两边被同一个错误假设污染**。
   现在 `verify.py` 里有一张 `EXTERNAL_CHECKLIST`，按**外部事实**（各章有几章几话）
   逐条核对；`fetch_all.py` 也会打印「各章收了几节」，某章为 0 会显式告警。

## 7. 这份语料在本项目里的位置

这个项目里有**两条独立的未花链路**，别搞混：

| | QQ 机器人 | 本机 DSH agent |
|---|---|---|
| 通道 | AstrBot（QQ 私聊/群聊） | DeepSeek Harness |
| 人格落点 | SQLite `personas` 表 | `agent/SKILL.md` → persona patch |
| 人格文本 | `qq-bot/persona/bot-personality.md` | `agent/SKILL.md` + `agent/knowledge/` |
| 平台规则 | 有 QQ 专属规则（分段、长度、禁 Markdown） | 有 DSH 专属规则（工具调用、场景描写） |

**本目录（`assets/story-cn/`）= 两条链路共用的原始素材层。**
它不属于任何一边，只提供事实与语料。人格怎么写、平台规则怎么定，
仍然分别在 `qq-bot/persona/` 和 `agent/` 里维护——**不要把平台规则写进语料库**。
